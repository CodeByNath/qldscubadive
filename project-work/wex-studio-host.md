## Builder — Phase 1I package pushed/deployed; real-server pointer activation unverified this session (17 October 2026)

**No WEX repository access this session** — confirmed; only the `staging-pointer.json` schema/values this file itself already supplied were used.

**Mechanism (`StudioStagingPointer.php`, new):** `StudioReleaseLock`'s constructor, when given no explicit pin (the production path), now resolves its pin once through this collaborator instead of its own four constants directly. Active only when `wp_get_environment_type() === 'staging'` — everywhere else, including a server where `WP_ENVIRONMENT_TYPE` is simply unset (WordPress's own default is `'production'`), it is a no-op and the fixed pin is unchanged; this satisfies item 3's "stop at the safety gate rather than unintentionally enabling auto-update on production" by failing closed to inert-by-default rather than by inventing a new environment signal. Validates the pointer's exact key set, `schema`/`contract` strings, an integer `sequence`, an allowlisted `change`, a `releaseId` matching WEX's naming shape, a `manifestPath` both URL-safe and *derived* from that `releaseId` (never trusted as an independent value), and a well-formed `manifestDigest`. A durable `get_option` record (`qsd_studio_pointer_state`) of the highest accepted `sequence` — never a transient — makes a replayed or downgraded pointer unable to move the release backwards even across a process restart; a higher sequence may still legitimately re-name an earlier release (rollback). A durable record that fails its own shape check is treated as tampered, not absent, and never resets the baseline. Bounded to one revalidation (and outage retry) per 300s. `previous` is validated for shape only, never required to chain, since a legitimately skipped sequence means it will not always match.
