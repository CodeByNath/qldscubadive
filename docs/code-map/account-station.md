# Account Station

Account is a singleton hierarchy — Account → Settings → Tools → Profile (Brand) — not a repeatable list entity. Exactly one of each node ever exists per site. Publish/Disable/Enable are computed by the shared [StationLifecycle](../../wp-content/plugins/qsd-platform/src/Modules/Admin/Support/StationLifecycle.php) engine, restricted to the `active`/`disabled` subset; Account mints no `draft`/`archived`/`trashed` record and wires no Archive/Trash/Restore/Delete. Whether that should instead become full travel-table conformance is an open exception proposal awaiting a Reviewer/Owner decision, not a settled exemption.

## Purpose and ownership

`src/Modules/Account/` is the single backend owner. Four permanent Platform ID prefixes — `QSDA`/`QSDAS`/`QSDAST`/`QSDASTP` — are declared once in `PlatformIdentifierPolicy`, each a string prefix of the next but disambiguated by total length. Identity for all four nodes is bootstrapped idempotently through the shared `PlatformIdentifierStation`, addressed by fixed native-reference strings (`account:root`, etc.), since each node is a singleton.

- [AccountRepository.php](../../wp-content/plugins/qsd-platform/src/Modules/Account/Support/AccountRepository.php) is the one aggregate's sole read/write path: a single non-autoloaded options row, written only through a `$wpdb`-level compare-and-swap commit loop, retried on every lost race, failing closed with `AccountStorageBusy` once exhausted. `commit()` short-circuits when the mutator's output already matches the row's bytes: real MySQL reports 0 affected rows for a matched-but-unchanged `UPDATE` (no `CLIENT_FOUND_ROWS`), indistinguishable from a lost race otherwise — the staging 503 on a repeat Brand Save.
- [AccountIdentity.php](../../wp-content/plugins/qsd-platform/src/Modules/Account/Support/AccountIdentity.php) sequences the four nodes parent-to-child; a dead request between a node's native write and the registry's bound-flip is finished via `assign()`, not re-minted. Each node's parent id is persisted and re-checked on resumption; a node with no recorded parent reads as unrecorded, not a mismatch.
- [AccountBrand.php](../../wp-content/plugins/qsd-platform/src/Modules/Account/Support/AccountBrand.php) holds Brand sanitization and calls `StationLifecycle` for its status writes: `publish()` is `statusRouteTransition(current, 'active', previous)`; `disable()` guards with `isLive($current)` — the same calls `ServiceController` makes. Brand has no required field, so it always settles cleanly; Enable always lands back on unmasked `disabled` (Pending), mirroring Service's mask exactly.
- [AccountMedia.php](../../wp-content/plugins/qsd-platform/src/Modules/Account/Support/AccountMedia.php) stores Brand logo/favicon uploads content-hash-addressed in their own uploads subdirectory — never the Media Library. Content is sniffed against a four-type allow-list; nothing stored is deleted.
- [AccountController.php](../../wp-content/plugins/qsd-platform/src/Modules/Account/Http/AccountController.php) owns every route: detail, bootstrap, Brand save/settle, media, and the Publish/Disable/Enable status route.

## Frontend

`resources/ts/account-station/` registers Account with Station Manager exactly as Service does, with a card surface instead of a catalogue:

- [register.ts](../../wp-content/plugins/qsd-platform/resources/ts/account-station/register.ts) registers the nav item, a `mode: 'card'` destination, the `account` data source, the `account-card` template kit, and the `account` drawer template. Admin authors the actual presentation placement in `admin-station/register.ts`'s `registerPresentationPolicy()`, exactly as it does for Service.
- [useAccountCard.ts](../../wp-content/plugins/qsd-platform/resources/ts/account-station/surface/useAccountCard.ts) and [AccountCard.tsx](../../wp-content/plugins/qsd-platform/resources/ts/account-station/presentation/AccountCard.tsx) are the Home surface: one `ReadBlock`, no grid. Deliberately a separate read from the drawer's own fetch, the same two-instance rule Service keeps.
- [AccountSettingsSection.tsx](../../wp-content/plugins/qsd-platform/resources/ts/account-station/presentation/AccountSettingsSection.tsx) is a second, plain presentation section beneath the Brand card. Renders `StationSettings` for `stationId="account"`. The actual relocation: `settings-station/register.ts`'s `settings.rezdy-importer`/`settings.api-keys` list `stationIds: ['account']` only — Services' own tab presents General only; the panels, data, and credential-broker backend are unchanged, only the reaching array moved.
- [AccountDrawerHost.tsx](../../wp-content/plugins/qsd-platform/resources/ts/account-station/surface/AccountDrawerHost.tsx) is a thin bridge (mirrors `ServiceDrawerHost.tsx`) mounting [entity-drawers/account/AccountDrawerContent.tsx](../../wp-content/plugins/qsd-platform/resources/ts/entity-drawers/account/AccountDrawerContent.tsx) through the shared `EntityDrawer`/Station Manager kit, restored after a staging defect where a simplified direct-`ReadBlock` drawer had diverged from the platform's established composition. `ACCOUNT_DRAWER_ENTITY` declares one module (`brand`) in `details` and an empty `connections` placement — the fixed two-tab bar still renders, with nothing under the second tab. The Brand binding/editor render through the same `OverviewShell`/`InlineEditorShell` every conforming Station uses; `useAccountDrawerController.ts` mirrors `useCategoryDrawerController.ts` at Account's one-module scale. The footer stays `EntityActionFooter` directly, never `CanonicalEntityFooter` (its overflow always offers Archive/Trash); `AccountDrawerDialogs.tsx` hand-authors Publish-confirm and unsaved-exit per the lifecycle contract's §11 convention.
- [useAccountStation.ts](../../wp-content/plugins/qsd-platform/resources/ts/account-station/useAccountStation.ts) takes no record input — only one Account ever exists. Save only writes the draft; Publish settles and activates in one backend call, so there is no separate user-facing Settle control.
- [api.ts](../../wp-content/plugins/qsd-platform/resources/ts/account-station/api.ts) maps wire snake_case to camelCase; media upload alone bypasses the shared JSON `apiClient` (`FormData`, since the backend reads a real `$_FILES` upload).
