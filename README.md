# QSD Platform — Queensland Scuba Diving

The business platform behind Queensland Scuba Diving. WordPress is the runtime and storage host only; this repository provides:

- **Stations** — Service and Category today, each with its own data, drafts, lifecycle, API and drawer.
- **Platform IDs** — permanent identifiers (`QSDS…` for Services, `QSDC…` for Categories) that are never reused, even after deletion.
- **Lifecycle engine** — Pending → Published (Active) → Disabled/Enabled → Archive/Trash → Restore/Delete, with per-module drafts and notification pills.
- **`qsd/v1` API** — every read and write goes through it; nothing is exposed through WordPress's own public pages or `/wp/v2`.
- **Admin Station** — the management app at `/station/` (login gate, light/dark theme, Station Home, drawers).

The public website is a separate front end that will read the API.

## Repository layout

```text
wp-content/plugins/qsd-platform/   the platform plugin
  qsd-platform.php                 bootstrap + built-in autoloader (no Composer)
  src/                             PHP: Core, Stations, Platform ID, Admin Station host
  app/modules/admin-station/       Admin Station document + login/denied templates
  resources/ts/                    Admin Station UI source (Preact + TypeScript)
  resources/css/, atomic-engine/   styles
  dist/                            built UI (generated by npm run build; not committed)
  tests/                           PHP contract tests (plain `php tests/x.php`)
  scripts/                         JS contracts and mounted lifecycle regressions
wp-content/themes/qsd-shell/       minimal runtime shell theme
docs/                              AI index, architecture contracts, Code Maps
AGENTS.md                          working standard for contributors and AI assistants
```

## Setting up a site

1. Copy (or deploy) `qsd-platform` and `qsd-shell` into `wp-content/` with a built `dist/`.
2. In WP admin: activate **QSD Platform** and switch the theme to **QSD Shell**.
3. Create business users with the **Platform Manager** role (`qsd_platform_manager`). WordPress administrators also have access.
4. Open `https://<site>/station/` and sign in.

The platform never creates accounts. Optional SMTP: define `QSD_SMTP_HOST`, `QSD_SMTP_PORT`, `QSD_SMTP_USER`, `QSD_SMTP_PASS` (and optionally `QSD_SMTP_FROM`, `QSD_SMTP_FROM_NAME`) in `wp-config.php`.

## Development

Tooling runs on a developer machine or CI only; the server never runs npm.

```sh
cd wp-content/plugins/qsd-platform
npm ci
npm run build        # dist/ for the Admin Station
npm test             # typecheck + PHP tests + build + JS contracts/regressions
npm run docs:check   # Markdown links, documented paths, Code Map index
```

PHP 8.0+ is required (tests run on the PHP CLI with WordPress functions stubbed).

## Deploying to staging

`.github/workflows/ci-deploy.yml` tests every push. Pushing the `staging` branch (or running the workflow manually) also copies the plugin's runtime files and the theme to the SiteGround staging site over SSH. It needs these repository secrets: `STAGING_SSH_HOST`, `STAGING_SSH_PORT`, `STAGING_SSH_USER`, `STAGING_SSH_KEY`, `STAGING_SSH_PASSPHRASE` (if the key has one), `STAGING_WP_PATH`.
